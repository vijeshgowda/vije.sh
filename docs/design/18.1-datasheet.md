# V18.1 · Datasheet, refined

Prototype: `../18.1-datasheet.html` · 127 KB raw, 37 KB gzipped · Uses `../shared/content.js` · Brief: minor changes to V18 (shadows, small placement changes, more animation), no dog card, no motorcycle tachometer; later, live data from 18.3 plus a catalogue of extra feeds to choose from.

## 1. Concept
V18 unchanged in spirit: vije.sh as the datasheet of a chip, VKG-04, with a pinout for navigation, a UART console, a self-healing cluster, a server rack, a timing diagram, a bit-register Lab, procedural photos, application notes and a forum "bus". 18.1 adds depth (soft and offset shadows), more motion, a real-time clock card in place of the dog and the tachometer, and a **Live telemetry** section fed by public APIs, with a Live page where feeds can be pinned to the overview.

## 2. Tokens
Fonts unchanged: Space Grotesk (400 to 700) and JetBrains Mono (400, 500, 700). Colours as V18 (`--bg #f4eee3`, `--ink #111214`, `--red #e30613`, `--red-t #c4050f` for small red text; dark: `--bg #0c0d0f`, `--ink #efefec`, `--red-t #ff4b55`). New tokens:

| Var | Light | Dark | Use |
|---|---|---|---|
| `--card` | `#f8f3ea` | `#121316` | raised surfaces (cards, tables, feeds) |
| `--sc` | `60 40 20` | `0 0 0` | shadow colour channels, used as `rgb(var(--sc)/a)` |
| `--sh1` | `0 1px 2px rgb(--sc/.08), 0 2px 6px rgb(--sc/.06)` | heavier black | resting shadow |
| `--sh2` | `0 2px 4px …/.07, 0 10px 24px -6px …/.18` | heavier black | panels, console, cluster |
| `--sh3` | `0 4px 8px …/.08, 0 22px 48px -12px …/.3` | heavier black | hover lift, rack, dialogs |
| `--shr` | `0 8px 22px -8px rgb(227 6 19/.55)` | brighter red | red glow (pods on hover) |

Buttons get a flat offset shadow `3px 3px 0 var(--line2)` (4px on hover, 1px when pressed). The red button keeps its cut corner, so it uses `filter: drop-shadow(0 6px 10px rgb(227 6 19/.35))` instead of box-shadow. Storage keys use the prefix `v181-` (theme `v181-theme`).

## 3. Page structure
Same routes as V18 plus one: `#/` overview, `#/work`, `#/lab`, `#/photo`, `#/blog`, `#/blog/{slug}`, `#/forum`, `#/forum/{id}`, **`#/live`** (nav item P7; the chip pinout still has six pins). Running footer reads "Page n of 7".

Overview order (changed): hero (wordmark, chip, UART) · ticker · 1 Features · 2 Cluster · **3 Live telemetry** · 4 Peripherals · 5 Latest application notes · 6 Absolute maximum ratings.

## 4. Components (changes from V18)
- **Header**: gains `--sh2` once the page scrolls past 8px (`.top.scrolled`). Nav links get an ink underline that grows from the left on hover.
- **Chip**: the body has a two-layer `drop-shadow` whose offset follows `--sx`/`--sy`; the whole SVG tilts in 3D (`rotateX/Y` up to 5°, perspective 900px on `.hero-r`) toward the pointer.
- **UART**: `--sh2`; each new line flashes red for .9s (`span.new`).
- **Section headings**: a 3px red bar under the heading grows from 0 to 4rem when the section is revealed.
- **Cards** (peripherals): no longer a hairline grid; separate cards with 1.25rem gaps, `--card` fill, `--sh1`, lift 4px with `--sh3` on hover, a red 3px top line that wipes in, and a radial red spotlight that follows the pointer (`--mx`, `--my`).
- **RTC card** (`.card.wide`, spans two columns, replaces WDT dog and THR tachometer): live clock `HH:MM:SS` (seconds red, colons blink), date line, a scrolling 32.768 kHz crystal sine (SVG path redrawn each frame while visible), and three registers: CAREER UPTIME (from 1 Sep 2017, as `{y}y {d}d {hh}h`), THIS SESSION, TIMEZONE (from `Intl`).
- **Tables, rack, Lab, photos, post, pager, forum**: raised with `--card` and `--sh1`/`--sh2`; rack units slide 6px on hover and 14px when pulled out; note and thread rows slide 4px and lift.
- **Dialogs**: `--sh3` and an open animation (fade + 14px rise).
- **Live feed card** (`.card.feed`): header `LF-nn` (red) and a status chip (dot + LIVE / CACHED n min ago / STALE / NO SIGNAL + host); title; body. Layout classes: `.w2` spans two columns, `.w3` spans the full row (HN, list in two columns). Lists use `.fl` rows: red index, title + mono meta, right-aligned value.
- **Globe** (LF-01): canvas inside `.gwrap` (min height 21rem, dotted grid background), "Follow ISS" toggle, "drag to rotate" hint, readouts LAT / LON / ALT KM / KM/H. Sphere filled from `--card` to `--faint` with a soft drop shadow; coastlines and dots in ink; ISS, its path and launch pads in red.
- **Live page** (`#/live`): intro, "On overview: LF-01, …" line, "Reset to LF-01 to LF-03", then the catalogue of 12 feed cards, each with an "Add to overview" / "On overview" toggle (`aria-pressed`, red when on, card border red).

## 5. Interactions
- Pointer over the hero tilts the chip and moves its shadow (fine pointers only, not under reduced motion).
- Section headings, cards, table rows, rack units, gallery figures, threads and feeds fade and rise in on scroll on every page (`.rv` uses the `translate` property so hover `transform` still works).
- Table numbers in the ratings table roll through random digits before settling.
- Lab: the GB figure pops on change; the 16 register cells flip in a staggered wave when the bit width changes.
- Feeds: hover a launch row to mark its pad on the globe; click it to turn the globe to the pad. Pins on the Live page are saved in `v181-feeds` and decide which feeds the overview shows (defaults `iss`, `man`, `hn`).
- UART logs feed events: ISS acquisition, next launch, HN frame count, pins added or removed.
- Typing "launch" still sends the rocket; "woof" no longer does anything.

## 6. Algorithms
- **Feed registry**: `FEEDS = { key: { code, title, host, cls, html?, mount(card, ok, fail, alive, body) } }`. `mountFeeds(root)` runs every `.feed` in the root; `ok(r)` sets the status chip, `fail()` shows NO SIGNAL with a Retry button that re-runs the mount. `alive()` turns false on route change so late responses are dropped.
- **Globe**: orthographic projection with centre `(lon0, lat0)`; a point is visible when `sin φ0 sin φ + cos φ0 cos φ cos(λ − λ0) ≥ 0`. Coastlines are all arcs of `land-110m` decoded from TopoJSON (delta-decoded, then `x·scale + translate`), drawn as polylines broken where they go behind. Day/night: about 4,000 dots on a 4° equal-area grid, bright if the dot product with the subsolar point is positive (subsolar latitude `−23.44° cos(2π(doy + 10)/365)`, longitude `−15° (UTC hours − 12)`). ISS path: 10 positions 10 min apart, each segment spherically interpolated (slerp) into 12 steps. Auto-rotate 0.004°/ms; "Follow" eases toward the ISS. Pointer drag rotates (0.35° per px).
- **Countdown**: `T-` or `T+` then `{d}d HH:MM:SS`, refreshed every second.
- **Space weather**: last 24 Kp values as bars (red at Kp ≥ 5), a dashed line at Kp 5, label "quiet", "active" (≥ 4) or "G1 to G5 storm" (`G = floor(Kp) − 4`).
- **Runtime lifecycle**: first 3 cycles not past EOL for Node.js and for Kubernetes; "LTS" when the LTS date has passed.
- Data sources, endpoints, limits and cache times: [live-data.md](live-data.md).

## 7. Responsive
- ≤ 62rem: cards and feeds two columns; the chip stops tilting.
- ≤ 48rem: one column; wide and full-row feeds drop to one column; globe readouts 2 × 2; the drag hint hides. V18's mobile rules still apply (hamburger, no running head, UART, firmware strip or applications list).

## 8. Accessibility and motion
- Feed cards are `article`s labelled by their title; the globe canvas is `aria-hidden` and its data is repeated as text (readouts, launch list).
- Pin toggles and Follow use `aria-pressed`; launch rows are buttons with a label that names the pad.
- Reduced motion: no tilt, spotlight, reveals, rolling numbers, register flips, crystal wave, globe auto-rotation or pulsing; the globe redraws only on data or drag.

## 9. Performance notes
- The globe draws only while on screen and the tab is visible; ISS polling pauses in hidden tabs.
- The Live page makes about 25 requests on a cold cache and almost none on a warm one. The overview with default pins makes ISS polls plus at most one Launch Library and one HN refresh per cache period.
- File size grew from V18 mainly because of the feed code (~13 KB raw).

## 10. Feedback and reuse
- User liked the ISS, launch manifest and HN downlink in 18.3 and asked for them here, plus more feeds to choose from. The Live page exists to make that choice; pinned feeds show on the overview.
- If a feed set is chosen for production, move Launch Library and GitHub behind a server cache (see live-data.md).
